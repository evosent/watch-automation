# Состояние автоматизации в версии 0.3.30

## Источники данных

| Этап | Постоянный источник | Временное состояние | Идентификатор |
| --- | --- | --- | --- |
| Входные модели | `modelCatalog` в IndexedDB, копии файлов в `assets` | фильтры панели | `skuKey`, `sourceVariantId`, SHA-256 входа |
| Очередь | `queue` и `generationMemory` в `chrome.storage.local` | рабочий слот | `sourceId`, `operationId`, `leaseId` |
| Генерация | `generationRevisions` в IndexedDB | вкладка ChatGPT и content script | `generationId` |
| Скачивание | проверенный PNG по точному пути | запись Chrome Downloads | `generationId`, `outputPath`, `outputHash` |
| Постпроверка | OCR в той же `generationRevision` | `postprocessTabs`, `factsProgress` | `generationId`, `factsJobId` |
| Галерея | каталог и актуальная ревизия | загрузка миниатюры | `generationId`, точный путь и SHA-256 |

Одна ревизия связывает исходную модель, конкретный чат, PNG и его OCR. Галерея
показывает актуальную ревизию из каталога. Соседний файл с похожим именем не
используется как замена. Старые физические ревизии и отклонённые карточки остаются
в истории/архиве. Сомнительные старые записи сохраняются как legacy.

## Состояния запуска и слота

Обычный запуск выбирает новые модели из сохранённого каталога. Очередь брака
выбирается отдельно. После `СТАРТ` каждому слоту выдаются `leaseId` и новый
`generationId`; все поля прежней ревизии очищаются. Рабочая вкладка создаётся в
окне панели. Проверка страницы начинает опрашивать вкладку после подтверждения
`PREPARE_PAGE_RUN`. До реального Send вкладка может загружать файлы и готовить
промпт. Общая пауза применяется только между реальными отправками.

`ПАУЗА` блокирует новые Send. Принятые запросы, загрузки и OCR продолжают
наблюдаться. Задания без отправленного промпта возвращаются в очередь; их
ревизии помечаются `CANCELLED`, указатель каталога на такую попытку снимается.
`ПРОДОЛЖИТЬ` использует сохранённый план и заново назначает только оставшиеся
модели. `СТОП` завершает сессию, сверяет уже проверенные результаты, закрывает
её рабочие вкладки и оставляет незавершённые модели доступными новому запуску.

При задержке уже принятого OCR-запроса вкладка остаётся в том же чате. Фоновая
проверка ищет полный JSON и сохраняет его в ту же ревизию. Через 15 минут без
полного ответа фиксируется ошибка. Исторические ошибки OCR можно повторно
прочитать вручную из галереи; завершённый запуск сам не открывает новые вкладки
после следующего старта браузера.

Статус `SAVED` публикуется после постоянной записи OCR в IndexedDB. Если хотя бы
один OCR завершился ошибкой, итоговый статус сообщает об ошибках спецификации.
Таймеры LIVE показываются только для текущих этапов; время терминальных
`SAVED` и `ERROR` не продолжает расти.

## Границы проверки

Автоматические тесты используют фиктивные файлы, IndexedDB и логику расширения.
Они проверяют версии SKU, точные hash/path-связки, брак, паузу, cooldown,
перезапуск, поздний OCR и неполный JSON. Реакцию живого сайта ChatGPT на
фоновую вкладку может подтвердить только отдельный контролируемый прогон в
профиле Chrome for Testing. Для такого прогона запускать профиль через
`START_AUTOGENERATION.cmd`, который устанавливает фоновые флаги Chrome.
