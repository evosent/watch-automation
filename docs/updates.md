# Обновления для пользователей WatchAutomation

## 0.3.53 — согласованная политика серий для брендов

- Для каждого бренда единообразно задаётся политика заголовка: серия обязательна, необязательна или запрещена.
- OCR-проверка спецификации, предупреждения и галерея применяют ту же политику; бренды без серии больше не получают ложных ошибок.
- Pagani Design распознаётся как двухстрочный брендовый блок; старые спецификации с `Design` в поле серии отображаются корректно.
- Передача результатов сохраняет версию раскладки и политику серии. В релизный пакет включены актуальные локальные референсы.

## 0.3.52 — восстановление сверки каталога и выгрузка диагностики

- Завершённые слоты с оставшимися `leaseId` больше не блокируют сверку каталога после прогона.
- Добавлена адресная локальная команда экспорта полного JSON прогона и журнала событий.
- Скрипт сбора автоматически снимает DOM текущих вкладок ChatGPT в окне автоматизации, добавляет сохранённые DOM-события и диагностические записи, затем упаковывает всё в ZIP.

## 0.3.51 — единый учёт результатов

Галерея, очереди, части и план запуска используют общую проверку готовности: изображение существует на диске, его SHA-256 совпадает с зарегистрированной версией, а спецификация относится к этому же изображению. Новая незавершённая попытка сохраняет уже принятый результат модели. Явная отметка брака требует нового результата.

Состав существующих частей сохраняется. При запуске выбираются оставшиеся задания в выбранной части с учётом лимита «Фото за запуск». Для сохранённых изображений без спецификации предусмотрено отдельное получение спецификации. Прогресс нового запуска считает полностью готовые результаты.

Перед исправлением старых идентификаторов создаётся резервная копия реестра. Неоднозначные соответствия сохраняются для проверки. Журнал регистрации изображений позволяет восстановить запись после прерванного сохранения. Недоступность локального сервиса помечает состояние проверки устаревшим и блокирует небезопасное планирование.

Эта запись описывает локальную сборку. Для распространения друзьям требуется публикация нового GitHub Release по инструкции ниже.

Вкладка «Сервис» проверяет последний стабильный GitHub Release. Для установки расширение использует локальный Node-сервис на `127.0.0.1`; он загружает и проверяет ZIP-пакет. Во время активного прогона файлы не заменяются: обновление ждёт освобождения рабочих вкладок.

В пакет входят папки `extension/` и `input-ref-images/`, а также файлы локального сервиса обновления. Промпты находятся в `extension/prompts/` и обновляются вместе с расширением. Папка `input-watches-images/` в пакет не входит и при установке не изменяется.

Начиная с 0.3.39 после успешной установки приложение перезапускается целиком: старый локальный сервис завершает работу, новый подтверждает готовность, затем закрывается и снова открывается только Chrome for Testing с профилем WatchAutomation. Обычный Chrome не затрагивается. Во время перезапуска панель временно теряет связь; это ожидаемый этап, проверка состояния повторяется до двух минут. Настройки, очередь и история сохраняются в прежнем профиле. Завершённым обновление считается после запуска обоих процессов. Ошибка перезапуска не означает откат уже установленных файлов; повторная проверка позволяет повторить перезапуск без скачивания того же пакета.

Изменение файлов на компьютере не публикует их в GitHub. Если последний release asset уже установлен, кнопка сообщает об актуальной версии. Для распространения исправлений нужен новый релиз и собранный ZIP. Переход со старого обновлятора, не допускающего `dev/control-routing.mjs`, выполняется через свежий bootstrap или полный комплект; исправленная кнопка старый whitelist задним числом не меняет.

## Публикация новой версии

1. Увеличить `version` в `extension/manifest.json`.
2. Собрать файлы командой `npm run build:release`. Она также запускает `build:update`; в `dist` появятся обновляющий ZIP, полный установочный ZIP, скрипты установки, TAR фототеки и манифест.
3. Создать стабильный GitHub Release с тегом `v<версия>`. Приложить `watch-automation-update.zip`, `watch-automation-bootstrap.zip`, `watch-automation-installer-package.zip`, `INSTALL_FROM_GITHUB.cmd` и `Install_From_GitHub.ps1`. Например:

   ```powershell
   gh release create v0.3.33 dist/watch-automation-update.zip dist/watch-automation-bootstrap.zip dist/watch-automation-installer-package.zip INSTALL_FROM_GITHUB.cmd Install_From_GitHub.ps1 --title "WatchAutomation 0.3.33" --notes "Обновление приложения и установщика"
   ```

Пользователям нужен доступ к публичному репозиторию. Если они уже используют сборку с кнопкой обновления, она скачает архив из последнего стабильного релиза. Для установки вручную запусти `UPDATE_WatchAutomation.cmd` после закрытия рабочего Chrome и подтверждения в консоли.

Для старой сборки без кнопки и без скрипта обновления: один раз скачай `watch-automation-bootstrap.zip` из [последнего релиза](https://github.com/evosent/watch-automation/releases/latest), распакуй его в корневую папку WatchAutomation и запусти `UPDATE_WatchAutomation.cmd`. В стартовом пакете лежат только скрипт и два файла обновлятора; входные фото и референсы он не содержит.

GitHub Releases поддерживает скачивание приложенного файла по стабильной ссылке на последний релиз: <https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases>.

## Установка через GitHub

Друзьям можно отправить прямую ссылку на командный установщик:
https://github.com/evosent/watch-automation/releases/latest/download/INSTALL_FROM_GITHUB.cmd

Он получает PowerShell-установщик из последнего стабильного релиза. Установщик загружает ZIP приложения через GitHub API, сверяет размер и SHA-256 с метаданными GitHub, затем скачивает фототеку из отдельного prerelease-релиза с тегом `watch-photos-v1`. В установочный ZIP входят исходники приложения и `input-ref-images/`, папка `input-watches-images/` исключена.

Фототека опубликована отдельным TAR-файлом, так как GitHub ограничивает размер каждого release asset значением меньше 2 ГиБ. Тег данных остаётся prerelease, поэтому он не подменяет последний стабильный релиз приложения. Установщик скачивает TAR только тогда, когда локальная `input-watches-images/` отсутствует или пуста. Если папка уже содержит изображения, локальная фототека сохраняется. Кнопка обновления в расширении передаёт только код, промпты и референсы.

После изменения состава фототеки выпусти новый тег данных и обнови его в `Install_From_GitHub.ps1`. Обычные обновления приложения не требуют публикации нового архива с часами.

Архив фототеки публикуется один раз отдельным prerelease:

   gh release create watch-photos-v1 dist/watch-photos-v1.tar dist/watch-photos-manifest.json --prerelease --title "WatchAutomation photo library v1" --notes "Первичная версия входной фототеки"
