# Watch Card ChatGPT Browser Automation

Инструкции по выпуску и установке обновлений находятся в [`docs/updates.md`](docs/updates.md).

Локальное Chrome Extension для пакетной генерации карточек часов через ChatGPT.
Расширение запускает от двух до шести независимых вкладок. Количество рабочих
вкладок выбирается в панели, а освободившийся слот получает следующую карточку
после подтверждённого скачивания результата.

## Входные данные

```text
input-ref-images\
    1. Base.png
    2. Ozon blind zones 2.png
    3. Logo Black.png
    brands\
        Casio\
            1. Casio.png
        Benyar\
            1. Benyar.png
        ...

input-watches-images\
    in_sale\*.png
    in_sale\bad_resolution\*.png
    not_in_sale\*.png
    not_in_sale\bad_resolution\*.png
```

В side panel выбираются две папки. Chrome требует явного выбора локальной папки,
поскольку расширение не может самостоятельно читать произвольные директории
Windows. После выбора папок сканирование выполняется автоматически.

## Сохранение выбранных папок

После выбора расширение сохраняет метаданные папок и копии входных файлов в IndexedDB
расширения. При повторном открытии панели файлы восстанавливаются автоматически, поэтому
перезагрузка расширения и обновление его кода через `Reload` не сбрасывают выбранные
входные данные. Для смены состава папки выбери её заново — новая выборка заменит сохранённую.

Chrome намеренно не передаёт расширениям полный абсолютный путь из обычного поля выбора
файлов. В панели сохраняется доступный относительный путь и рабочая копия файлов.

## Брендовые профили и референсы

В папке `extension\prompts\brands` находятся отдельные локальные профили для 12 брендов,
обнаруженных в каталоге фотографий: Casio, Orient, Tissot, Pagani Design, Benyar, Q&Q,
Seiko, Citizen, Longines, Diesel, Armani Exchange и Certina. Общий файл `Base Prompt v4.txt`
сохраняет базовую механику, профиль бренда добавляется к нему автоматически.

Во время генерации расширение определяет бренд по имени исходного файла, передаёт
соответствующий брендовый шаблон `1. <бренд>.png` (поддерживается также имя `1. Base.png`),
затем добавляет карту слепых зон Ozon и профиль этого бренда. В качестве общей карты
поддерживаются `2. Ozon blind zones.png`, `2. Ozon blind zones 2.png` и
`2. Base n Ozon.png`. Если брендовый шаблон отсутствует, используются общие файлы из
корня `input-ref-images`. Общий `Logo Black.png` остаётся третьим референсом для всех брендов.

Список серий в каждом профиле закрытый. Перед генерацией модель ищет точную серию по
полному названию и артикулу в интернете, отдавая приоритет официальной карточке бренда,
каталогу и инструкции. Найденный результат проходит нормализацию и сверку с локальным
словарём профиля. В карточку попадает только точное совпадение с этим словарём;
интернет не может добавлять новые значения. При отсутствии подтверждённого совпадения
профиль либо использует явно разрешённый fallback, либо включает режим без серии.
Сейчас fallback `Classic` задан только для обычных неименованных моделей Casio
после поиска. Для остальных брендов при отсутствии подтверждения первая строка блока
названия остаётся пустой, бренд переносится на позицию второй строки, код сохраняется
на фиксированной третьей позиции. Имя файла служит подсказкой для поиска, его
содержимого недостаточно для подтверждения серии.

В каждой карточке обязательны две отдельные подтверждённые УТП, водозащита и числовой
размер корпуса. Для круглых часов размер берётся как диаметр. Для квадратных,
прямоугольных и цифровых моделей используется наибольший размер корпуса из записи
производителя; прочерк и пустое значение запрещены. Внутри одного прогона повторные
сигналы окна «Слишком много запросов» объединяются: отсчёт начинается с первого
сигнала и не продлевается дубликатами. Длительность выбирается в поле «Пауза лимита»
перед запуском (от 1 до 30 минут). Уже отправленные генерации продолжают
наблюдаться и скачиваться, пока новые отправки ожидают окончания паузы.

## Работа панели

На вкладке «Запуск» выбираются обычная очередь или отдельная очередь брака,
категория, бренд, количество вкладок и лимит фото. «Модели» показывает каталог и
фильтры без ручной смены статусов. Папки и повторное сканирование расположены на
вкладке «Сервис». Промпт берётся из `extension\Base Prompt v5.txt`.

- `СТАРТ` открывает рабочие вкладки в том же окне Chrome, где открыта панель.
- `ПАУЗА` прекращает новые отправки. Уже отправленные изображения и OCR продолжают
  наблюдаться и сохраняться. `ПРОДОЛЖИТЬ` возвращает тот же сохранённый план.
- `СТОП` завершает сессию, закрывает её рабочие/OCR-вкладки и возвращает
  незавершённые модели в очередь. Подтверждённые PNG и ревизии сохраняются.

Подробная схема переходов и источников данных: `docs/architecture-0.3.30.md`.

## Постоянная история

Снимок входных моделей и их тегов хранится в IndexedDB (`modelCatalog`). Вкладки
«Модели» и «Запуск» читают этот сохранённый каталог. Его меняет первоначальный выбор
папки и явная команда пересканирования на вкладке «Сервис»; Reload расширения и
перезапуск Chrome сами по себе не запускают повторный обход папки и не возвращают
успешные SKU в очередь. Одному SKU могут соответствовать несколько входных файлов
из разных категорий: каталог сохраняет их отдельными вариантами с тегами продажи и
качества. При сканировании содержимое сверяется по SHA-256, поэтому замена файла с
сохранёнными размером и датой всё равно обновит его статус. Удалённый источник
помечается отсутствующим, а история генераций сохраняется.

Каждая отправленная генерация до запроса получает уникальный `generationId`. В
`generationRevisions` сохраняются SKU, вариант и hash входа, чат, `factsJobId`,
точный путь и SHA-256 PNG, полный OCR-ответ и временные отметки. До отправки запроса
ревизия получает `generationId` и состояние `GENERATING`; после проверки скачанного
PNG она остаётся `FACTS_PENDING`, пока полный JSON не будет записан и подтверждён как
`READY`. Обычная очередь берёт только новые SKU и модели с изменившимся источником или
рецептом; изображение с незавершённой спецификацией восстанавливает OCR без повторной
генерации. `SAVED` публикуется после записи ревизии в IndexedDB. История,
`generationMemory` и завершённые ревизии переживают обновление расширения и Chrome.

Галерея строит карточки из каталога и указателя последней готовой ревизии. Из Downloads
она получает только конкретный `outputPath` и сверяет его с сохранённым hash; соседний
файл с похожим именем или более новой датой не может заменить PNG карточки. Сканирование
папки результатов используется для счётчиков и диагностики. Если точного файла нет или
hash расходится, галерея показывает ошибку изображения.

Кнопка `Брак · перегенерировать` архивирует только PNG выбранного `generationId` после
проверки пути и SHA-256, убирает его спецификацию из активной карточки и ставит SKU в
отдельную очередь брака. Обычный запуск эту очередь пропускает; её можно выбрать на
странице запуска. Предыдущие ревизии и OCR остаются в истории для диагностики. Если
пометить брак во время генерации этой же модели, активная попытка завершается, затем
отдельная очередь выполняет новую ревизию.

Старые данные без достоверных `generationId + outputPath + outputHash` не соединяются
по имени модели или файла. Они остаются в legacy-хранилищах и не становятся активной
карточкой галереи или целью архивирования. Надёжно связанные ревизии постепенно
переносятся в каталог; исходные старые stores не удаляются.

## Результат

```text
Downloads\WatchAutomation\<queue-group>\<исходное имя>__<generationId>.png
```

Имя модели берётся из имени исходного файла без расширения. В промпте поддерживаются
плейсхолдеры `[вставь нужную модель часов]` и `{{MODEL_NAME}}`. Перед скачиванием
страница отдаёт найденный результат в content script; при доступности содержимое
переводится в полноценный PNG исходного размера, поэтому расширение сохраняет
именно картинку из ответа, включая пропорции 3:4. Прямой URL остаётся резервным
вариантом для случаев, когда страница отклоняет чтение бинарного содержимого.

## Ошибки и диагностика

Сообщения об ошибках, подтверждения очистки и удаления записей показываются встроенным
блоком в side panel. Браузерные `alert/confirm` в рабочем интерфейсе расширения не используются.
Ошибка запуска, DOM, ответа ChatGPT, таймаута, закрытия рабочей вкладки или скачивания
помечает только проблемную карточку. Если генерация уже была отправлена, её слот остаётся
под наблюдением и забирает результат при позднем появлении. Если ошибка произошла до отправки
генерации или страница вернула окончательный ответ без картинки, слот сразу получает следующую
карточку; проблемная запись остаётся в текущем прогоне для повторного запуска через
`ПРОДОЛЖИТЬ`. Успешно скачанные записи всегда пропускаются по постоянной истории.
Состояние и выбранный режим DOM-диагностики сохраняются в `chrome.storage.local`. Кнопка `ПРОДОЛЖИТЬ`
перезагружает сохранённые рабочие вкладки, подключает актуальную версию content script и
повторно проверяет видимые результаты. Это позволяет восстановить старые вкладки после
обновления расширения и сохранить уже готовую картинку.

Во время запуска service worker дополнительно проверяет все активные вкладки через DOM и
сверяет незавершённые загрузки через Downloads API. Это покрывает задержки фоновых вкладок,
пропущенные события страницы и завершившиеся скачивания, о которых браузер не успел сообщить
сразу. Проверки всех слотов выполняются параллельно с отдельным таймаутом транспорта, поэтому
зависшая вкладка не блокирует остальные. Для давно не отвечавших вкладок выполняется отдельный
фоновый probe; активное пользовательское окно и его вкладка не меняются.
Четыре референса одной карточки отправляются в ChatGPT одним событием `change` через
`DataTransfer`; для интерфейсов с однофайловым input сохраняется последовательный fallback.
Интервал 8–12 секунд относится только к отправке генераций между слотами и не добавляется
между загрузками четырёх референсов внутри одной вкладки.
Ответ без изображения получает окно ожидания 10 минут, а смонтированный, но ещё загружающийся
элемент изображения продолжает проверяться без этого ограничения. После ошибки уже запущенный
слот наблюдается до 15 минут. Отправка генераций разделена случайными интервалами 8–12 секунд.
В боковой панели отображаются общий статус, таймер паузы, отдельная карточка каждой рабочей
вкладки и короткий журнал внизу. Карточка показывает текущую фазу, номер попытки, время
последнего прогресса и состояние наблюдения. Если во всех активных слотах пять минут нет
нового ответа, изображения или смены состояния, очередь ставится на паузу и для каждого
слота сохраняется DOM-диагностика. При появлении окна «Слишком много запросов» расширение
нажимает «Понятно», фиксирует ограничение и блокирует только отправку новых промптов на
выбранный интервал. Пока таймер идёт, готовые изображения скачиваются и проверяются,
завершённые вкладки закрываются, следующие вкладки открываются и получают четыре
референса. После снятия ограничения общий планировщик отправляет подготовленные промпты
по очереди с интервалом 8–12 секунд. Кнопка «Открыть папку загрузок» показывает папку
последнего результата через системный проводник; если результатов ещё нет, открывается
страница загрузок Chrome.

Постоянный сбор DOM по умолчанию выключен, поэтому рабочие вкладки не получают observer,
периодические снимки и поток событий. В панели можно выбрать режим `Только при ошибках`
для редких диагностических снимков или `Полный журнал DOM` для исследования поведения
страницы. Полный режим заметно увеличивает нагрузку на браузер и диск.
События проходят через service worker и watcher и записываются в
`diagnostics\dom-library\<дата>\<session>.jsonl`; при временной недоступности watcher
они остаются в ограниченном буфере `chrome.storage.local`. Кнопка `Очистить DOM-архив`
удаляет накопленные DOM-состояния и снимки из буфера расширения и двух диагностических
каталогов. Доступны локальные endpoints `/status`, `/dom-events`, `/diagnostics`,
`/clear-diagnostics` и `/observations` (для сводки последних сессий используй
`/observations?latest=1`). При изменении файлов watcher вызывает `chrome.runtime.reload()`,
а после безопасной перезагрузки обновляет открытые страницы ChatGPT, чтобы новый
content script действительно подхватился. Во время активной генерации это действие
откладывается.

## Установка

Для автоматической установки передай на компьютер ZIP и расположенный рядом
`INSTALL_WatchAutomation.cmd`, затем запусти этот CMD-файл. Установщик распакует
комплект в `%LOCALAPPDATA%\WatchAutomation\WatchAutomation`, проверит Node.js и
зависимости, установит официальный Chrome for Testing и запустит его с изолированным
профилем. PDF-инструкция откроется в отдельном полноэкранном профиле. Установщик также
создаст на рабочем столе ярлык `Автогенерация — профиль`, который запускает этот же
Chrome-профиль напрямую.

При отсутствии Node.js установщик использует `winget`, затем официальный MSI с
`nodejs.org`. Требуется интернет-соединение и подтверждение UAC. Пакет не содержит
`node_modules`: watcher не имеет внешних библиотек, команда `npm install` выполняется
для проверки среды и будущих расширений.

Chrome for Testing скачивается с официального канала Chrome for Testing в
`%LOCALAPPDATA%\WatchAutomation\ChromeForTesting`. Он нужен для автоматической загрузки
распакованного расширения: начиная с Chrome 137 обычные branded-сборки Chrome игнорируют
флаг `--load-extension`. Пользовательское окно Chrome при этом не используется.

Если комплект уже распакован, запусти его внутренний `INSTALL_WatchAutomation.cmd`.
Для обычного запуска готовой установки используй `START_AUTOGENERATION.cmd`.
Вход в ChatGPT и выбор двух папок выполняются при первом запуске. Для часов выбирай
корень `input-watches-images`, где находятся `in_sale` и `not_in_sale`; после выбора
большой папки дождись завершения сохранения и появления списка моделей.

После первой установки для последующих запусков используй ярлык `Автогенерация — профиль`
на рабочем столе. Ярлык запускает Chrome for Testing с профилем
`%LOCALAPPDATA%\WatchAutomation\ChromeProfile`, URL ChatGPT и параметром загрузки
распакованного расширения. При переносе папки комплекта на другой путь повторно запусти
установщик: он обновит ярлык с новым путём.

Ручная установка для разработки:

1. Открой `chrome://extensions`.
2. Включи Developer mode.
3. Нажми Load unpacked.
4. Выбери папку `extension`.
5. Открой side panel расширения.

## Автообновление распакованного расширения

Для разработки запусти в корне проекта:

```powershell
npm run watch:extension
```

Также можно запустить файл `watch-extension.cmd` двойным щелчком. Watcher следит
только за папкой `extension` и поднимает локальный endpoint на
`http://127.0.0.1:17321/status`. Расширение периодически получает контрольную сумму
файлов и вызывает `chrome.runtime.reload()` после изменения. Первый запрос после
запуска watcher формирует исходную контрольную точку, поэтому лишней перезагрузки
при старте процесса нет.

Если в этот момент идёт генерация, перезагрузка откладывается до безопасного состояния.
Окно watcher нужно оставить запущенным во время разработки. Выбранные папки, очередь,
история и состояние хранятся в `chrome.storage.local` и при перезагрузке расширения
сохраняются.

Для запуска изолированного профиля Chrome for Testing с этим watcher используй
`launch-automation-profile.cmd`. Рабочие вкладки откроются в отдельном окне без перевода
фокуса с пользовательского окна. Профиль Chrome хранится в `%LOCALAPPDATA%\WatchAutomation\ChromeProfile`,
поэтому его не требуется переносить вместе с архивом. Watcher запускается автоматически
при наличии Node.js 18+; установщик поставит Node.js, если его нет.
После обновления launcher закрой старое окно автоматизации один раз, чтобы профиль
освободился и его занял Chrome for Testing. Личные окна Chrome закрывать не требуется.

Watcher проверяет скачанный PNG через endpoint `/output-verify?path=...&expected=...`:
путь принимается только внутри папки `WatchAutomation`, а basename сверяется с ожидаемым именем;
дополнительно endpoint сверяет сигнатуру PNG,
наличие блока IHDR, размеры, размер файла и SHA-256. Расширение сохраняет результат проверки
в памяти генерации и принимает карточку готовой только после завершившейся загрузки.

## Управление из Codex

Watcher предоставляет локальный канал управления, поэтому запуск можно выполнять
из рабочего процесса без ручного открытия страницы расширения:

```powershell
$body = @{ command = 'start'; payload = @{ runLimit = 15 } } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:17321/control `
  -ContentType application/json -Body $body
```

Поддерживаются команды `start`, `continue`, `stop` и `status`. Расширение забирает их
через service worker, сохраняет результат и повторно не выполняет уже обработанную
команду. При `start` и `continue` можно передать `queueGroup`, `runLimit` и `workerCount`.
